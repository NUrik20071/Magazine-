# Полный магазин «Тихо» — публикация и управление с Android

Этот репозиторий уже содержит React frontend, Express API, Clerk-аутентификацию, Drizzle-схему PostgreSQL и административные маршруты. Патч добавляет production-раздачу frontend из API-сервера и конфигурацию Render.

## 1. Что понадобится

- аккаунт GitHub;
- аккаунт Render;
- аккаунт Clerk (для входа пользователей);
- Android: Chrome и приложения GitHub/Render необязательны — можно всё делать в браузере.

## 2. Загрузить проект в GitHub

1. Распакуйте архив и загрузите всё содержимое репозитория в новый приватный или публичный GitHub-репозиторий. Не загружайте `.git` из ZIP, если он есть; не добавляйте `.env` с секретами.
2. Убедитесь, что в корне есть `render.yaml`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` и папки `artifacts/`, `lib/`.
3. В Render нажмите **New + → Blueprint**, подключите репозиторий и примените `render.yaml`.

## 3. Настроить Clerk

1. Создайте приложение в Clerk Dashboard и включите вход по email (verification обязательна для админ-доступа).
2. Скопируйте Publishable Key и Secret Key из раздела API keys.
3. В Render → сервис `maghazin-tovarov` → Environment задайте:
   - `CLERK_PUBLISHABLE_KEY` = Publishable Key;
   - `VITE_CLERK_PUBLISHABLE_KEY` = тот же Publishable Key;
   - `CLERK_SECRET_KEY` = Secret Key;
   - `ADMIN_EMAILS` = ваш подтверждённый email (можно несколько через запятую).
4. Сохраните и выполните **Manual Deploy → Deploy latest commit**, чтобы Vite пересобрал frontend с publishable key.
5. В Clerk разрешите домен Render (`…onrender.com`) в настройках доменов/redirect URLs, если Clerk Dashboard этого требует.

**Никогда не помещайте `CLERK_SECRET_KEY` в переменные с префиксом `VITE_`, frontend-код, GitHub или сообщения.**

## 4. База данных

Blueprint создаёт PostgreSQL. Команда запуска выполняет `pnpm --filter @workspace/db run push`, чтобы применить Drizzle-схему при первом старте. Для серьёзного production-магазина позже переведите изменение схемы на версионируемые миграции, а не синхронизацию при каждом старте.

После успешного запуска проверьте `https://ВАШ-СЕРВИС.onrender.com/api/healthz` — ожидается JSON со статусом `ok`.

## 5. Использование на телефоне

- Откройте URL сервиса в Chrome.
- Войдите через «Войти».
- Админ-ссылка появится для пользователя с разрешённым email; если не появилась, откройте `/admin` и проверьте `ADMIN_EMAILS` и подтверждение email в Clerk.
- Для установки ярлыка: Chrome → меню ⋮ → **Добавить на главный экран**.
- Добавление/изменение/удаление товаров выполняется в `/admin`; товары хранятся в PostgreSQL, корзина пока сохраняется локально в браузере конкретного устройства.

## 6. Если деплой не прошёл

- Ошибка `Missing VITE_CLERK_PUBLISHABLE_KEY`: задайте ключ в Render Environment и заново выполните Manual Deploy.
- Ошибка `DATABASE_URL`: проверьте, что база из Blueprint создана и привязана к сервису.
- Ошибка `PORT`: Render должен передавать `PORT=10000` (переменная задана в Blueprint).
- Пустая страница: откройте Render → Logs и проверьте ошибку сборки; отдельно проверьте `/api/healthz`.
- Нет доступа в админку: `ADMIN_EMAILS` должен содержать точный подтверждённый email, без лишних пробелов.

## Примечания

- Render Free может засыпать после периода бездействия и иметь ограничения на бесплатную базу/ресурсы; это не гарантия круглосуточной работы без задержек. Перед реальными заказами проверьте условия актуального тарифа.
- В текущем коде корзина не создаёт заказ и не принимает оплату. Это полноценный каталог с API и админкой управления товарами, но checkout, платежи, доставка и уведомления требуют отдельной реализации.
